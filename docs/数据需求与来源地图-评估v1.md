# 《数据需求与来源地图 v1.0》第一版评估

> 评估日期：2026-09-02；评估对象：外部《数据需求与来源地图 v1.0》
> 评估基准：当前库实际状态（1200 品种 / 75 分子 / 881 文号 / 医保目录 3453 条目 / 政策 59）

## 1. 总评

文档方法论正确（**从功能反推字段、四层结构、受控枚举、人工核查期**），
且与我们已落地的 schema v1.0 基本同构（A 品种层 ≈ drug_molecule，B 文号层 ≈ drug_registration）。
结论：**方向完全可用，按现状微调后可作为"数据库搭全"的施工图**。

需要修正/补充的三点：
1. **C 价格层是真实缺口**：当前 schema 没有价格时序表（价格散落在医保条目和 extra_data），
   做不了趋势与归一比价——必须新增 `price_history` 表。
2. **市场层（A3/A4 中患者池、销售额、渗透率）建议独立成 M 层**：这些是"分析结论+估算"而非
   基础数据，混进品种层会污染主数据；应单建 `drug_market` 表，带 置信度/口径/来源/估算日期。
3. **A4"省内患者池 + 全国市场"目前全库缺失**：需新增字段建模（全国/湖南患者池、确诊率、
   处方渗透率、计算公式留痕），属人工估算，必须标注来源与置信度。

## 3. 与当前库的差距清单（"搭全数据库"还差什么）

### 3.1 需要新增的 schema
- `price_history`：价格时序表（价格/类型[挂网|中标|集采中选|零售]/生效日期/来源 URL/核查日期/核查人）——**最高优先**
- `drug_market`：市场层（全国/湖南患者池、确诊率、处方渗透率、年销售额、口径/置信度/估算日期）
- `drug_molecule` 补字段：指南推荐等级、给药途径、冷链、专利到期日、迭代链/代次、拓展适应症
- `drug_registration` 已有：文号状态、上市许可持有人（已采集，需回填）

### 3.2 需要填充的既有表
- `policy_drug_relation`：0 → 全量关联（政策-品种）
- 医保匹配：3453 条目录 vs 品种匹配 74 条 → 用分子层再跑一轮匹配（阿法替尼等 9 厂家聚合后匹配率应大增）

### 3.3 需要新建的采集器（Playwright 可过）
- CDE 说明书采集器（适应症/机制/给药/冷链）——P3 核心
- CDE 过评名单采集器（集采风险输入）
- CDE 临床试验登记采集器（在研管线）
- 集采登录采集器（路线 B，用户账号）

### 3.4 纯人工（瓶颈，需分批）
- 指南推荐等级（先肿瘤）、湖南患者池估算、大白话沟通字段、年销售额、专利到期日

## 4. 建议补齐顺序（按性价比）

1. **建 price_history + drug_market schema**（一次性，解锁价格与市场层）
2. **分子层重跑医保匹配**（低成本高收益，匹配率预计大幅提升）
3. **CDE 说明书采集器**（Playwright，一次打通适应症/机制/给药/冷链）
4. **集采情报**（登录采集 + 第12批 xlsx → 集采风险自动推导）
5. **政策-品种关联填充**（关键词+人工确认）
6. **人工字段分批**（先肿瘤指南等级 + 湖南患者池试点）

## 5. "数据准确是死线"的落地保障

- 唯一主库：git 内 data/drugs.json + SQLite 三层约束（已具备）
- 清洗规则全测试防回退（已具备，103 测试）
- 每人/爬虫字段带 来源 URL + 核查日期；超期（180 天）自动进核查提醒队列（需加 `reviewed_at` 字段与提醒脚本）
- 人工估算字段（市场层）强制带 置信度 + 口径说明，前端区分"官方数据/人工核验/估算"
- 集采/医保等多源交叉验证（易联 + 联采办 + 各省平台）

## 6. 一句话结论

这份来源地图可直接作为"数据库搭全"的施工图；当前最缺的三块是
**价格时序表、市场层建模、CDE 说明书/过评采集**；人工瓶颈（指南、患者池）按病种分批推进。
