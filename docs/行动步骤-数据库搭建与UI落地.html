三、最终阶段：UI 优化（第三步）

目标：清晰、便捷、横纵向对比、药品-政策关联。数据库搭全后逐项落地：

  • 一药一页升级：接 molecule 层——一个品种页聚合 多厂家/文号/规格（横向卡片）+ 医保/集采/政策时间线（纵向）
  • 同病种横向对比：分子层为基，按 疾病领域/病种 聚合，对比 医保状态/挂网价/厂家数/是否独家/指南等级
  • 政策关联视图：政策卡片挂接品种（国谈/目录/集采/双通道），品种页反向展示"政策路径"
  • 集采情报页：批次 × 品种 × 中选企业 × 价格，新批次提醒
  • 数据标注：官方数据 / 人工核验 / 估算 三色标注，来源+更新时间可见

四、"数据准确是死线"的保障机制

  • 唯一主库：git 内 data/drugs.json + SQLite 三层约束（已具备）
  • 清洗规则全测试防回退（103 测试，进 CI）
  • 每个字段带 来源 URL + 核查日期；超期（180 天）进核查提醒队列（待加 reviewed_at）
  • 人工估算（市场层）强制带 置信度 + 口径；前端区分 官方/核验/估算
  • 集采/医保多源交叉验证（易联 + 联采办 + 各省平台）
