## 一、第三方依赖韧性（CDN 多源回退 + 降级）

**问题**：ECharts 与 pinyin-pro 原先只从 jsdelivr 同步加载，且 ECharts 使用处没有任何存在性检查。大陆网络下 jsdelivr 一旦不通，打开「竞争格局 → 迭代时间线」会直接报错，整个模块不可用。

**改动**：
1. 两个同步 `<script>` 替换为内联多源加载器，依次尝试 `jsdelivr → unpkg → npmmirror`（已逐一验证可达）。
2. 加载改为异步，不再阻塞页面首屏。
3. ECharts 使用处加保护：组件加载失败时，迭代时间线区域显示提示并保留下方数据表格；`libReady` 机制会在图表库恢复加载后自动补绘图表，无需刷新。
4. pinyin-pro 原本已有 `window.pinyinPro` 存在性检查，多源加载后行为不变：加载失败时拼音搜索自动失效，其余功能不受影响。

## 二、数据持久化加固（localStorage 自动备份与恢复）

**问题**：药品库、政策库、评分权重全部只存 localStorage：主键数据一旦损坏（写入中断、格式错误、误导入脏数据），应用要么丢数据回退示例，要么直接启动失败（权重损坏时整站白屏）。

**改动**：
1. 每次保存前自动把上一版本写入备份键：`drug_db_v2_backup`、`policy_db_v1_backup`。
2. 读取时先校验主库：JSON 非法或数组元素不是对象时，自动回退读取备份；备份也损坏才回退内置示例数据。
3. 评分权重加载改为安全解析：损坏 JSON、非法值、超范围值都会被忽略并合并默认权重（不再有整站白屏风险）。
4. 导入 JSON 时校验记录有效性：药品导入会跳过无 `gn`/`bn` 的记录并提示；政策导入校验失败时保留原数据，明确提示"原数据未受影响"。

## 三、DOCX 导入修复

**问题**：docx 解析条件过宽，会把页眉、页脚、脚注等 `word/*.xml` 一起拼进正文，导入的文本内容不干净。

**改动**：只提取 `word/document.xml` 正文。

## 部署步骤

1. 用本目录 `index.html` 替换仓库根目录同名文件（建议先备份原文件）。
2. `git add index.html` → `git commit` → `git push`（GitHub Pages 会自动发布）。
3. 发布后验证清单：
   - 打开网页，确认四个模块正常渲染；
   - 「竞争格局 → 任选病种」确认迭代时间线图表正常；
   - 在「数据管理」导入一次旧版导出的 JSON，确认正常入库；
   - 断网/屏蔽 cdn.jsdelivr.net 后打开页面，确认页面不白屏、迭代时间线显示降级提示；
   - 如浏览器此前已打开过旧版，请强制刷新（Ctrl+F5）避免缓存。
